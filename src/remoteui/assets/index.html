Work authorization

Each role is a separate server-authorized session, sent as a header — never a role claimed in the request body. Anything outside a role's authorization is refused server-side.

Contract amendment

A contract amendment starts with a company admin requesting it inside Remote's own product, then the employee and the employer consenting to it. Everything after the request is the real thing: the checks (identity → employment → the country's own amendment form → payroll cutoff) run first, and only then is a support ticket raised — already tagged with the decision and carrying the drafted summary, ready for the two signatures in Remote's support desk.

ℹ This is a stand-in, not Remote's real platform. A contract amendment is really requested inside Remote's own product, a surface this project cannot host. This page is a demonstration stand-in for it, so the flow can be shown from its true starting point; its employees are fixtures, and nothing on it is Remote's product, Remote's design, or a Remote endpoint.
