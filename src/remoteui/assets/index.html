Contract amendment

UC-06 starts with a customer admin requesting an amendment inside Remote's own product, then the employee and the employer consenting to it. Everything after the request is the real thing: the actual UC-06 gates (identity → employment → per-country schema → payroll cutoff) run first, and only then is a Zendesk ticket created — already tagged with the decision and pre-filled with the drafted summary, ready for the two-role approval in the ZAF sidebar.

ℹ This is a stand-in, not Remote's real platform. UC-06's real trigger — a contract amendment requested inside Remote's own product — has no public API, which is the whole reason UC-06's Zendesk intake exists. This page stands in for that one missing surface so the flow can be demonstrated from its true starting point. Nothing on this page is Remote's product, Remote's design, or a Remote endpoint.
