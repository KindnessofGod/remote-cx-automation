1. **Every ticket-filed resignation settled in USD.** `831f822` stopped the
   portal denominating a Portuguese settlement in dollars; the second execution
   path never got it. `normalizeResignationRequest.js` filled an absent
   currency with `'USD'`, the gates body did it again as `request.currency ||
   'USD'` and never read the employment record, and the twin's
   `reconcilePtoPayout` did it three more times. Invisible to parity because
   every scenario passed `"USD"` explicitly. Now: one exported
   `payoutCurrencyFor()` in `src/uc05/ptoPayout.js` — stated, else Remote's own
   `contract_details.compensation_currency_code`, else nothing, and nothing
   refuses the line — read by `workflow.js`, the gates body and the parity
   harness. A structural test reads all five files for a `USD` fallback.
2. **The Zendesk note printed `PTO payout: 0.00 USD (from no_time_off_records)`**
   for a resignation filed with no balances — a settlement of nothing, in a
   currency nobody stated, the reason hidden in an enum. Same defect the ZAF
   sidebar row had (`07f15a7`). Now *"not known — … not a finding that nothing
   is owed"*, the portal's words.
3. **The graph refused every real Sandbox employee at gate 3.** The twin's
   normaliser read `start_date` / `basic_information.start_date` — the
   stand-in's ENRICHED shape, filled for exactly two hard-coded ids in
   `src/remotebridge/enrichment.js` — while the real record carries
   `provisional_start_date`, which `normalizeEmployment()` on the src path has
   read since `DEMO-COUNTRIES.md` §958. Executions **11936** (João Silva) and
   **11939** (Inês Carvalho), both PT, both `provisional_start_date
   2023-06-26`, both `escalate / missing_seniority_date` with the date on the
   record. Every earlier live UC-05 proof used an enriched id. Precedence now
   mirrors `normalizeEmployment()`; a parity test compares the two normalisers
   directly over five shapes, because the harness feeds `evaluate()` the NODE's
   normalised record and so could never see this.
