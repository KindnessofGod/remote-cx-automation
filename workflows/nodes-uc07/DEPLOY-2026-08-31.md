# UC-07 live-graph deploy — 2026-08-31, `Relocation Gates` + `Escalate Relocation Ticket`

Everything below is prepared, tested and **not deployed**.

`WORKFLOW_UC07_ID` was read live on 2026-08-31 (12 nodes, `active: true`,
`versionId === activeVersionId === 3f8983a9-2aed-44f2-90c6-af773fc2e446`) and
the node parameters quoted as "old" below are that capture, verbatim.

Read `CLAUDE.md` §7b before doing any of it. The two rules that matter here:
`PUT /api/v1/workflows/{id}` **publishes in place** (the MCP `update_workflow`
only drafts), and the only thing that answers "is this live?" is
`activeVersionId === versionId` read back afterwards.

**Order is not optional.** Change 1 (the `Relocation Gates` body) must land
first. Change 2 interpolates `internalNote`, which does not exist until it does.
Deploying the node first would give every relocation ticket a note consisting of
"Dossier record: …" and the routing sentence — no narrative and **no disclaimer
at all** — on a fully green execution with nothing red anywhere. An n8n
expression that dereferences a field nothing produces renders as an EMPTY
STRING.

UC-07 is 🔴 and every run escalates: `relocationGates.js` sets

## What the retired sentence got wrong — two defects in one string

The live `updateFields.internalNote`:

```
=AI research dossier {{ $('Create Dossier Record').item.json.id }} — {{ $('Relocation Gates').item.json.dossier.narrative }} RESEARCH SUPPORT ONLY, not a decision to proceed. For review by a qualified Remote Mobility Legal specialist. {{ $('Assign Routing').item.json.routingNote }}
```

### 1. It dropped half the disclaimer, and the half it dropped covers exactly what the note then prints

The canonical string is a dossier **field**, `framing`, written identically by
`relocationGates.js`'s `buildDossier()` and by `src/uc07/dossierBuilder.js:228`:

> RESEARCH SUPPORT ONLY — not a relocation decision **or a legal, immigration,
> or tax determination**. For review by a qualified Mobility Legal specialist
> (Tier-3).

The node's paraphrase kept "not a decision to proceed" and silently dropped
"or a legal, immigration, or tax determination". So a Tier-3 specialist was told
the dossier is not a go/no-go and was **not** told that its immigration and tax
content is not a determination — while the very next thing the note prints is
that content. On a real run the dossier's `requiredActions` are literally
`IMMIGRATION_ASSESSMENT`, `PE_REVIEW`, `TAX_REVIEW`, and the narrative spells
out `UC07_IMMIGRATION_REQUIRED`, `UC07_TAX_RESIDENCY_REVIEW_REQUIRED` and
`UC07_PE_RISK_REVIEW_REQUIRED` in prose.

`framing` is stored in `uc07_dossiers.dossier` and rendered in the ZAF panel. It
had never been written to the ticket at all.

**The fix is not a better paraphrase.** `composeInternalNote()` interpolates
`dossier.framing` **verbatim**, so the sentence exists in exactly one place and
the ticket, the stored row and the ZAF panel carry the same words by
construction rather than by anyone remembering to update three copies. A test
asserts it appears **exactly once** — a paraphrase riding alongside the
canonical sentence would be worse than either.

`test/n8nUc07Parity.test.js` could not have caught this: it deep-equals the
whole DOSSIER against `buildDossier()`'s, `framing` included, and passes while
the ticket carries a different sentence — because the ticket's sentence is not
in the dossier at all.

### 2. "AI research dossier" is false on this path

`WORKFLOW_UC07_ID` has twelve nodes and **not one is an LLM call**: webhook, two
Code nodes, four Supabase, one Zendesk, one NoOp, the trace pair, and
`Assign Routing`. Everything the note prints is deterministic —
`draftNarrativeTemplate()` is a template, `retrieveMobilityGuidance()` is
keyword matching over a local corpus, and `faithfulness` is the explicit
`{verdict: "not_evaluated"}` sentinel precisely because no judge can run in a
Code node.

`src/uc07/workflow.js` **does** have an LLM `draftNarrative()` seam — but this
note only ever rides the n8n graph, where that seam does not exist. The label
oversold a deterministic artifact to the one reader whose whole job is to weigh
how much of it to trust. Dropped; the note states the provenance of each part
instead.

## UC-07 is 🔴 — the constraint the new prose is written under

No execution path may exist, and that holds today in three places at once: this
graph has no decision branch, `src/uc07/dossierStore.js` has one write method
and zero mutation methods, and the UC-07 API has no POST route.

A ticket note is a **fourth** surface where the guarantee could be given away —
not in code, in prose. So **nothing `composeInternalNote()` authors uses an
approve / authorise / proceed / sign-off verb, in any form, even negated**, and
`test/n8nUc07TerminalZendeskNodes.test.js` asserts it over the composed note
with `narrative` and `framing` subtracted. Those two are
`src/uc07/dossierBuilder.js`'s own reviewed sentences, quoted verbatim, and they
use those verbs precisely to negate them ("That is NOT an approval — this use
case has no execution path, and a human decides"). A bare scan over the whole
note would fire on exactly the disclaimers the note exists to carry.

**The raw verdict token is deliberately not printed.** `dossier.verdict` is one
of `BLOCK` / `REVIEW` / `PROCEED`, and "Gate verdict: PROCEED" on a 🔴 ticket is
a permission word three words from a specialist's eye. Nothing is lost:
`VERDICT_WORDS` renders all three in the narrative, each with its own caveat
attached, and the token survives on the dossier row and in ZAF.

## Change 2 — `Escalate Relocation Ticket`

Type `n8n-nodes-base.zendesk`. `authentication`, `operation`, `parameters.id`,
`group`, `status`, `tags` and credentials **unchanged**.

**`updateFields.internalNote`**

- old: the string quoted at the top of this document.
- new:
  ```
  ={{ $('Relocation Gates').item.json.internalNote }}

  Dossier record: {{ $('Create Dossier Record').item.json.id }}

  {{ $('Assign Routing').item.json.routingNote }}
  ```

Nothing is lost. The dossier row id and the narrative the old note printed are
both still there; what is added is the **whole** framing sentence, the flag
counts by severity, the required actions, the cost-estimate status with its
pending quotes, the real provenance of each part, and a closing paragraph saying
where the request is worked and why nothing here can act on it.

**`.item` and not `.first()`, on purpose.** This node already addresses
`$('Relocation Gates').item.json.externalRef` and
`.item.json.dossier.narrative` and has been proven working by real executions
(10710). UC-02's sibling spec takes `.first()` for its own graph and says why;
the difference is that UC-02's chain is eight hops and crosses a node with
`onError: continueRegularOutput`, while this one is a straight line of five and
is already proven on `.item`. Rewriting a proven expression to match a different
graph's is how a prose change becomes an outage.

**Not `$json`.** At this node `$json` is whatever `Assign Routing` emitted.
`Assign Routing` happens to spread its own input today, which is exactly what
makes `$json` the wrong thing to depend on.

**The dossier reference and the routing sentence are appended HERE** rather than
composed into `internalNote`, because both are produced by nodes downstream of
the gates: the Supabase insert has not run when the gates run, so the row id does
not exist yet, and neither has `Assign Routing`. `Dossier record:` is the only
hand-typed prose left on this node — three words, a label for a value, with
nothing in it to be wrong about, and a named constant in the spec so the test
can assert on it.

**No `publicReply`, and that is load-bearing.** Nothing on this graph replies to
the requester: the customer-facing acknowledgement lives on the dossier as
`customerFacingAcknowledgement` and is sent, if at all, by whoever works the
request. A reply field here would put a 🔴 dossier's contents in front of the
requester with no specialist between. The checker refuses one.

**`updateFields.tags`** — unchanged. The queue tag is **already live** here
(rca-iih7 / D-14, deployed by the pass that owns
`workflows/nodes/escalationQueueTagSpec.js`) and is reproduced below only so the
block is complete and pasteable.

```json
{
  "group": "={{ $('Assign Routing').item.json.zendeskGroupId }}",
  "internalNote": "={{ $('Relocation Gates').item.json.internalNote }}\n\nDossier record: {{ $('Create Dossier Record').item.json.id }}\n\n{{ $('Assign Routing').item.json.routingNote }}",
  "status": "open",
  "tags": [
    "uc07_escalated",
    "={{ $('Assign Routing').item.json.routing.queueTag }}",

  ]

```

## Proving it afterwards

Drive one real ticket and **read the ticket back**, never the run status. A
green node that wrote an empty note is the exact failure this expression can
produce, and every layer reports success when it happens.

UC-07's graph was last driven through its production webhook on 2026-08-30
(execution `10710`, `pinData: None`, US → NL). That run is marked `error` in n8n
and was still proof: the single failing node was the final Zendesk write, on a
descriptive `externalRef` where Zendesk wants a numeric ticket id, downstream of
every durable write. **For this deploy that node is the one being changed, so a
descriptive ref proves nothing** — raise a real ticket carrying `uc07_test` and
the employment field `9990000000001`, and then open it.

On the ticket, check for all five of:

1. the headline "a compiled RESEARCH DOSSIER";
2. the narrative;
3. the **whole** framing sentence, including "or a legal, immigration, or tax
   determination", appearing **once**;
4. "Dossier record: `<uuid>`" — and that the uuid resolves to a real
   `uc07_dossiers` row;
5. the routing sentence naming the owning team.

If 3 is missing or truncated, the deploy did not take. If 4 is empty, the
expression is reaching a node that had not run.
