## What is NOT changing, and why each is a plausible-looking wrong move

- **`status` stays `open` on all four.** Zendesk's `pending` means "waiting on
  somebody who is not us". Every one of these four is queued work on this side —
  two waiting on signatures taken in the ZAF sidebar, two waiting on a
  specialist. (UC-04's nodes are `pending` because they genuinely wait on the
  customer's own manager. Nothing on UC-09 does.)
- **The outcome tags stay.** `uc09_awaiting_dual_approval`,
  `uc09_awaiting_triple_approval`, `uc09_escalated`, `uc09_exception` are machine
  markers for a STATE, and the state was never what was wrong.
- **The two `Flag Awaiting …` nodes get NO queue tag.**
  `assignRouting.js`'s `isEscalation()` matches `/^escalat/i`, so it is false for
  `dual_approval_required` / `triple_approval_required`; `routingTag` **already
  resolves to** the queue tag on that branch and a second copy would be
  redundant. Same measured reasoning as UC-04's `Flag Blocked Workation`.
- **`={{ $('Assign Routing').item.json.routing.queueTag }}` on the escalate and
  unrecognised nodes is already live** (rca-iih7 / D-14 landed before this pass)
  and is owned by `workflows/nodes/escalationQueueTagSpec.js`, not by this spec.
  It is reproduced above only so the blocks can be pasted whole.
  `terminalZendeskNodeIssues()` deliberately does not assert it — two checkers
  asserting one field is how a fix in one lands as a failure in the other.
- **`Unrecognised Adjustment Decision` still does not carry
  `{{ $('Create Adjustment Record').item.json.id }}`.** It never did. The
  interpolation WOULD resolve on that branch (`Create Adjustment Record` is
  upstream of `Route by Decision` on every path), so adding it is a reasonable
  follow-up — but this pass owns the prose, and quietly adding a field while
  claiming to fix a sentence is how a spec becomes a place changes hide.

## Follow-ups with known sites

1. **Wire the four checkers into `scripts/lib/deployedNodeMappings.mjs`'s
   `STRUCTURAL_MAPPINGS`** and drop the four rows from
   `scripts/lib/unguarded-node-baseline.json` in the same change, so the
   coverage ratchet reports it if a row is ever dropped. Out of this pass's
   ownership (`scripts/lib/*` was off limits to it). Until then only the
   hermetic check runs.
2. **`summary` divides by 100 for every currency.** Wrong for a zero-minor-unit
   currency: 500 JPY renders as `5.00 JPY`. Fixing it needs ISO 4217's
   per-currency minor-unit table, which this repository does not have and must
   not invent — prime directive 4, and money is the one thing the substitution
   ladder forbids fabricating outright. A guessed exponent moves a real
   payment's decimal point by 100 in either direction and nothing downstream
   would notice. Stated at the site in `adjustmentGates.js`.
3. **`summary` omits the gross/net clause** `src/uc09/workflow.js` appends
   ("gross" / "net" / *"with no gross/net basis stated — do not sign without
   it"*), and its echo of the original request text. The same integer moves a
   different amount of money under each reading. One parity pass over the whole
   summary template, not a prose fix.
4. **The intake-trigger loop guard.** UC-04's `flagAwaitingApprovalSpec.js`
   argues for adding `uc_processed` to all four terminal nodes on every graph.
   Nothing sets it anywhere today, so every one of these nodes' own ticket
   update re-satisfies UC-09's intake trigger and the graph re-fires itself —
   harmless durably (the claim node conflicts and it stops at
   `Duplicate Delivery — Stop`) but not free, because `Fetch Employment
   (Remote)` runs before the claim. Apply to all four or to none.
